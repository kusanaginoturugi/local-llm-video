# 第5弾のメモ：スキャンした本を OCR して検索できる PDF にする

## 方針（2026-11-12）

- 最低限の手順だけを見せる：NDLOCR-Lite を入れる → `ocr.py --sourcepdf … --pdf-output …` の 1 本 → ビューアで検索。
  精度を上げる工夫（余白つき再認識、YomiToku との突き合わせ、パ／バの辞書、ローカル LLM の判定）は割愛し、一言だけ触れる。
- 制作者の実例は自炊した市販の本。著作権があるので、書名・ページ数・処理時間だけにして、ページ画像も本文も出さない。
- 画面に出すデモは、国立国会図書館デジタルコレクションの保護期間満了（PDM）の本：
  江戸川乱歩『一寸法師』（1935）pid 1170887、全 208 コマ、見開きのカラー撮影。`demo/fetch_ndl.sh` で取ってくる。
  ほかに見た候補：『鶉籠』1907 pid 885509（マイクロフィルム、いちばん汚い）、『吾輩は猫である』1930 pid 1184660、
  『芥川竜之介集』1927 pid 1173830、ポオ『黒猫』1923 pid 978046。どれも PDM。
- 制作は Claude Code（第4弾は Codex）。Codex は「クソまじめな猪突猛進タイプ。一緒に考えてじっくり作りたいと『まってくれー』と思うことが多かった。
  でも指示したことはちゃんとできるし、つむぎの絵もさらっと作ってくれた」（制作者）。台本のネタにしてよい。

## NDLOCR-Lite の PDF 出力（e57f7c6、本家のまま）

- `ocr.py --sourcepdf IN.pdf --output DIR --pdf-output OUT.pdf --pdf-render-dpi 300` で、画像はそのままに透明な文字を重ねた PDF ができる。
  本家の README には `--sourcepdf` と `--pdf-output` の説明がない（`ocr.py --help` には出る）。
- 出力ディレクトリ（`--output`）がないと、`Output Directory is not found.` と 1 行出すだけで何も作らずに終わる。終了コードは 0。先に `mkdir` する。
- 計測のときは、GPU に VOICEVOX ENGINE・whisper-server・llama-server が常駐していた（合わせて約 7.2GB）。NDLOCR を同時に 2 本走らせると cuBLAS の確保に失敗する。
- 速さ（自炊本の 6 ページ、300dpi、`Total PDF calculation time`）：CPU（Core i5-13400F）7.0 秒、GPU（RTX 4070、`--device cuda`）2.0 秒。
- 文庫 1 冊（自炊した『夏への扉』356 ページ、300dpi、v1.4.0）：CPU 350 秒（5 分 50 秒、約 1.0 秒/ページ）、GPU 68 秒（1 分 8 秒、約 0.19 秒/ページ）。約 5 倍。どちらも 356 ページの PDF ができた。
- GPU は `onnxruntime` を `onnxruntime-gpu[cuda,cudnn]==1.31.1` に入れ替える。CPU だけでも動く（制作者：「CPU だけでも使えるってことは言っていい」）。
- 2026-11-11 に本家が v1.4.0（a25d456）になった。動画用の環境は `demo/setup.sh` で clone した v1.4.0。PyPI にはまだ 1.4.0.dev0 しかないので、README どおり clone して `pip install -r requirements.txt`。
- `pdftotext` で抜くと、句読点が縦書き用の字（`︒` `︑` `︱`）になる。句読点込みの語は、ビューアによっては検索に引っかからないかもしれない（未確認）。

## クリーニングの前後（一寸法師 40・100 コマ、2026-11-12）

制作者の自炊用の背景補正（ぼかした紙の明るさとの差が 25 を超えた分だけを字にする）を、そのまま NDL の見開き写真にかけた（`demo/clean.py`）。

- 見た目は白い紙に黒い字になって、ずっと読みやすい。
- そのまま：句がまるごと抜けた箇所が 4 つ（「それから、」「分らないのは山野さんの心持です。」「それにはね、」「ゝ」）。
- クリーニング後：抜けは拾えたが、漢字の読み違いが増えた（銀座→鋸座、指環→振環、本當→未當、紋三→鮫三、山野家→出野家、
  堅苦しい→聲苦しい、激した→灣した、頑固者→頃同者、親戚→巴波 など、2 コマで 13 か所ほど）。この本は墨が薄く、細い線が削れる。
- しきい値を緩める（差 8、3 倍）と、抜けは拾えたまま、読み違いは 40 コマでほぼ 0、100 コマで 7 か所ほど。
- 正解のテキストはないので、ここの「正しい」は画像を見て決めた。2 コマだけの結果。

## 青空文庫との突き合わせ（一寸法師、GPU の OCR、2026-11-12）

- 青空文庫の『一寸法師』（作品 58053）は、底本が光文社文庫『江戸川乱歩全集 第2巻』（2004）で新字・新かな。1935 年版（旧字・旧かな）とは表記も版も違う。
  そこで `demo/compare_aozora.py` で、1 字 1 行にして GNU diff で並べ、本の中で 3 回以上出る置き換え（賣→売、ゐ→い など）と、
  くの字点・々の繰り返しは表記の違いとし、残りを誤りの候補にした。句読点・括弧・記号は数えない。小書きの仮名は大きい仮名にそろえる。
- 範囲は OCR の 6〜114 コマ（『一寸法師』の本文。この本は『乱歩傑作選集 第四巻』で、後ろに『屋根裏の散歩者』などが続く）。青空文庫の「作者の言葉」と全集の注は外した。
- 本文 87,044 字（OCR）、青空文庫 88,206 字。表記の違い 6,195 字。誤りの候補 628 か所・1,671 字（CPU の OCR でも 623 か所・1,671 字）。
- 候補から 40 か所を無作為に選び（`demo/crop_candidates.py`、種 1）、原本の画像で Claude が判定した（`demo/sample-verdicts.tsv`）。制作者の確認はまだ。
  - OCR の誤り 15 か所：漢字の読み違い（屋臺→屠懸、可哀相→可良相、爪磨→爪麟、禍→福、尾行者→尾行石、躙→躍、搬→撒、失戀者→失機者）、
    ピ→ビ、「て」の重複、抜け（が／その上、／イ、エ、／その最中に、／擊者（多くは同）。
  - 版・表記の違い 25 か所：書棚→書だな、此→この、稱してゐる→いう、無氣味→不気味、文面等も說明→文面等を説明 など。
    全集では「癩の樣に」が削られている。
- 見積もり（直す前）：候補 1 か所あたり誤りの字 0.725 → 約 455 字、正解率約 99.5%。
- 見直し（advisor の指摘）：
  - 挿入の位置が 1 字ずれていた（`after` が 1 字前から始まる）。直すと 4 番は「だが」2 字の抜けで、候補 1 か所あたり 0.75 字 → 約 471 字。
  - 青空文庫側が 200 字以上の塊を数えずに捨てていたので、表示するようにした。この本では 0 件（ページや列ごとの抜けはない）。
  - 「表記の違い」に回した組（`ndl/aozora-cuda.ortho.tsv`）にも誤りが紛れていた。3 回以上くり返す誤りがここに入る。
    怪しい組から 36 か所を画像で確認（`ndl/ortho-check.png`）。ビ→ピ・天→夫・父→又は誤り、小→少もおそらく誤り。
    た→と（たうとう）・ま→も（拒まう）・初→始・物→者（曲物）・が→は などは原本どおり。て→で は画像で決めきれない。
    濁点・半濁点の取り違え（ビ／ピ 16、ボ／ポ 8、ば／ぱ 6、バ／パ 4、ぽ／ぼ 3）と、天→夫 4・父→又 3・叔→紋 3・盆→益・小→少 を足すと 56 字。て→で が 23 字。
  - 合計で約 530〜550 字。1 万字あたり約 60 字、字の正解率は約 99.4%（幅を見て 99.1〜99.7%）。台本は「だいたい 99.4 パーセント、一万字に六十字くらい」。
  句読点を数えていないこと、標本が少ないことに注意。抜けは句ごと落ちるので、字数では大きく効く。

## クリーニングの前後（一寸法師 全 208 コマ、GPU、青空文庫との突き合わせ）

版の違いはどの実行でも同じなので、誤りの候補の増減を OCR の誤りの増減とみなせる。

| 画像 | OCR の字数（6〜114 コマ） | 表記の違い | 誤りの候補 |
| --- | --- | --- | --- |
| そのまま | 87,044 | 6,195 字 | 628 か所・1,671 字 |
| 白く（差 25・2 倍、自炊用の既定） | 87,503 | 6,081 字 | 1,443 か所・2,441 字 |
| 白く（差 8・3 倍） | 87,387 | 6,030 字 | 1,179 か所・2,018 字 |

- 白くすると読めた字は 350〜460 字増える（抜けが減る）が、読み違いがそれ以上に増え、差し引きでは悪くなる。緩めても元の写真に届かない。
- 2 コマだけ見たときは「痛み分け」に見えたが、1 冊では負け。
- 制作者の本番の手順（非公開のリポジトリ）でも、OCR は補正前の原本にかけ、背景補正と傾き補正は閲覧用 PDF の画像にだけ当てている。白くするのは読む人の目のため。台本はこれに合わせた。

## 端末の実録（2026-11-13）

- `video/termrec.py` で、`ocr.py` を仮想の端末で動かし、出た文字と時刻をそのまま `demo/rec/bunko-{cuda,cpu}.jsonl` に記録した。
  動画はこの記録を時刻どおりに再生して作る（デスクトップの画面録画ではない）。冒頭のコマンド行は、実際に流したコマンドから python のパスだけを短くしたもの。
- 自炊した『夏への扉』356 ページ、300dpi、v1.4.0。GPU 67.5 秒、CPU 356.7 秒（約 5.3 倍）。GPU に常駐していたのは whisper-server と VOICEVOX ENGINE（llama-server は止まっていた）。
  前日の計測（GPU 68 秒、CPU 350 秒）とほぼ同じ。台本は「約 6 分」「1 分 8 秒」「約 5 倍」。
- 画面に出るのはコマンド・ページ番号・書名だけで、本文も画像も出ない。
- `demo/rec/bunko-cpu-vs-gpu-x5.mp4`：左右に並べて 5 倍速（33 秒）。15 秒目で GPU が終わり、CPU はまだ 72/356 ページ。
  作り方：`termrec.py render … --speed 5`（CPU は `--until 165`）→ ffmpeg の hstack と drawtext でラベル。zsh では `$F:textfile` の `:t` が修飾子になるので `${F}` と書く。
