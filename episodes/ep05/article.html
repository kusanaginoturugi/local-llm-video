ローカル LLM で遊ぼう　第5弾の解説

スキャンした本を、検索できる PDF にする

自炊した本の PDF は、中身がページの写真だけなので、検索しても 0 件です。国立国会図書館の OCR「NDLOCR-Lite」で文字を読み取り、透明な文字としてページに重ねると、見た目はそのままで検索とコピーができるようになります。この記事は、そのいちばん短い手順と、動画で見せた計測と答え合わせの条件をまとめたものです。

しくみ写真の上に、見えない文字を重ねる

OCR はページの画像から文字の位置と中身を読み取ります。NDLOCR-Lite は、その文字を元の位置に透明なテキストとして書き込んだ PDF を出せます。下の図は、その透明な文字をわざと青く描いたものです。縦書きの列の上に、きちんと重なっています。

手順 1NDLOCR-Lite を入れる

必要なのは git と Python 3.11 以上です（本家の README には 3.10 以上とありますが、v1.4.0 のパッケージ設定は 3.11 以上）。GPU がなくても動きます。

git clone https://github.com/ndl-lab/ndlocr-lite
cd ndlocr-lite
pip install -r requirements.txt
cd src

仮想環境を分けたいときは python3 -m venv や uv venv で作ってから入れてください。動画では 2026-11-11 に出た v1.4.0（コミット a25d456）を使いました。

手順 2コマンド一本で、検索できる PDF を作る

mkdir out
python3 ocr.py --sourcepdf book.pdf --output out \
  --pdf-output book-ocr.pdf --pdf-render-dpi 300
  • --sourcepdf：読ませる PDF（スキャンした本）
  • --output：作業用のフォルダ。ページごとの文字（txt・json・xml）がここに出ます
  • --pdf-output：できあがりの、検索できる PDF
  • --pdf-render-dpi：ページを画像にするときの細かさ。既定は 150。文庫の小さい字には 300 にしています

落とし穴：--output のフォルダが無いと、Output Directory is not found. と 1 行出すだけで、何も作らずに終わります。終了コードも 0 なので、スクリプトに組み込むと失敗に気づけません。フォルダは先に作っておきましょう。

手順 3（任意）GPU で速くする

NVIDIA の GPU があれば、onnxruntime を GPU 版に入れ替えて --device cuda を付けるだけです。CUDA と cuDNN も pip で一緒に入ります。

pip uninstall onnxruntime
pip install 'onnxruntime-gpu[cuda,cudnn]==1.31.1'
python3 ocr.py --sourcepdf book.pdf --output out \
  --pdf-output book-ocr.pdf --pdf-render-dpi 300 --device cuda
本CPU（Core i5-13400F）GPU（RTX 4070）
文庫 356 ページ（自炊、300dpi）356.7 秒（約 6 分）67.5 秒
一寸法師 208 コマ（見開きの写真）295 秒105 秒

時間は time で測った実行全体（モデルの読み込み込み）。計測中も、GPU には VOICEVOX ENGINE や whisper-server などが常駐していました。NDLOCR-Lite を GPU で 2 本同時に走らせると、メモリが足りずに cuBLAS の確保で落ちました。見開きの大きな写真では GPU の差が小さくなります（約 2.8 倍）。

確かめる検索とコピー

できた PDF を Firefox で開いて「明智」を検索すると、『一寸法師』の 1 冊（208 コマ）で 289 件見つかりました。文字を抜き出すと、旧字体もそのまま入っています。

pdftotext -f 40 -l 40 book-ocr.pdf - | head

縦書きの句読点は、縦書き用の字（︒ ︑ など）として入ります。句読点まで含めた語で検索すると、ビューアによっては見つからないことがあるので、語だけで探すのが確実です。

答え合わせ字の正解率は、約 99.4%

99.4%

『一寸法師』は青空文庫にもあるので、OCR の結果と 1 文字ずつ突き合わせました。ただし青空文庫は 2004 年の全集が底本で、新しい字と今のかなづかいに直されています。そこで次のように見積もりました。

  1. 空白・句読点・括弧を除き、小書きの仮名を大きい仮名にそろえ、ゝ・々を前の字に開いて、1 字 1 行にして diff で並べる。
  2. 本の中で 3 回以上出る置き換え（賣→売、ゐ→い など）と、くの字点の繰り返しは「表記の違い」として外す。残りの 628 か所が誤りの候補。
  3. 候補から無作為に 40 か所を選んで、元の画像で確かめる。OCR の誤りは 15 か所、残り 25 か所は版の違いで、OCR は原本どおりでした。
  4. 「表記の違い」に紛れていた、何度も繰り返す誤り（ビ／ピの取り違え、山野夫人→天人 など）を 36 か所の画像で確かめて足す。

本文約 8 万 7 千字のうち、誤りは約 530〜550 字。1 万字に約 60 字です。句読点は数えておらず、標本も小さいので、99.1〜99.7% くらいの幅で見てください。

やってみた紙を白くしてから読ませると、悪くなった

紙の茶色やしみを抜いて白くした画像を OCR に渡すと、抜けていた字は拾えるようになる一方、墨の薄いこの本では細い線まで消え、読み間違いがそれ以上に増えました（紋三→鮫三 など）。

OCR に渡した画像読めた字誤りの候補

白くする（制作者の自炊用の設定）87,503 字1,443 か所

制作者の自炊本でも、紙を白くするのは読む人の目のためで、OCR には白くする前の画像を読ませています。

この先残り 0.6% は、手間がかかる

動画では割愛しましたが、制作者の手元では次のような工夫を重ねています。最初の 99.4% はコマンド一本、残りを削るのにもう二週間かかっています。

  • 行の画像に余白を足して、文字の認識だけをやり直す（枠が数ピクセル違うだけで句が抜けることがある）
  • もう一つの OCR（YomiToku）と読み比べ、食い違ったところだけを拾う
  • ルビを本文から外す。パ／バの取り違えは、単語を切り出して読み直す
  • 傾いたページはまっすぐに直し、OCR は直す前の画像で読ませて、文字の位置だけ回して重ねる
  • 決まらない食い違いはローカル LLM（Gemma 4 12B）に、順番を入れ替えて二回聞く。最後は人が画像で決める
  • 原本が旧字体で統一されている字は、対応表で直す（掴→摑）
